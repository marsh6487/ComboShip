## Design

1. Keep the optional reward identities, prerequisites, prices, Yes/No interaction, native held-item presentation, durable receipt transaction, and native quest rewards. Repair the message-owner and dialogue-lifecycle boundary in the OoT reward adapter. A first interaction must resolve the intended reward without relying on stale `msgCtx.talkActor`; accepted dialogue must survive native textbox startup and put-away delays. Unknown or stale custom interactions must never fall into a stock trade tutorial.
2. Reproduce the failures by executing production reward and native interaction/message functions with actual native structs. Use stubs only for external storage, rendering, audio, and unrelated engine services. Test the first interaction, Yes, No, delayed open/close, exact grant and permanent collection, repeated callbacks, stale or cancelled receipts, save failure, and preservation of trade slots/flags. Sweep the fixed OoT reward manifest wherever the same path applies and retain MM Hourglass/Whip receipt controls.
3. Restore the Whip reticle on MM's native aiming path without depending on the unused legacy first-person timer. Extend lash reach from 520 to 1040 engine units by changing the actual extension lifetime consistently with speed and rendering capacity in both games. Preserve the existing 136-unit fixed swing length, release physics, and combat responses. The existing red geometry aim marker must use the same maximum range as the lash; keep its existing color semantics without introducing an attachability indicator. Keep the existing beam/bar/actor grip rules; do not make arbitrary flat platforms or walls grapple targets. The exact authored Woodfall crossing remains a runtime check unless its collision data can be measured locally.
4. Later user steering explicitly authorizes moving the Rod to the center of Lost Woods room 0 so it is visible on entry. Ground the position in actual room geometry and retain loaded-floor/water/wall safety; constrain it to room 0. Preserve all other locations. Investigate delayed reward appearance and the separate MM randomizer starting-check delay. Reduce proven avoidable delays while retaining transition, collision, ownership and receipt safety; do not assume the two latency reports share a cause.
5. The later MM Lost Woods report also covers Saria and Epona appearing after the scene. Reproduce creation timing using native main/update/draw ordering and incoming transition behavior. Allow the two exploration companions to exist before the room is revealed, while retaining loaded-room, floor, resource, authored-actor and duplicate checks, prologue exclusions, death/game-over and outgoing-transition guards. Keep native interaction behavior and Termina Field's song-giving Saria timing unchanged. Separate actor creation timing from resource, native actor initialization and GPU visibility proof.
