# Magic and hallmark hint selectors — cumulative POC4

The MM Desired Items catalog now includes **Magic Stat Upgrade**, a hint-only identity for fractional upgrades owned by OoT. Existing saved item IDs are preserved: the selector ID is appended before RI_MAX. It is not added to a generated item pool and has no native grant path. An MM check containing the real foreign Magic Stat Upgrade resolves to this selector through its saved foreign metadata. Traps and unrelated foreign items cannot impersonate it.

Saria's priority picker now offers Progressive Magic, Power of Magic (the first native meter), Magic Upgrade (double magic), fractional Magic Stat Upgrade, and the previously excluded progressive sword, bow, bomb-bag, wallet and Goron Lullaby families. It also accepts the concrete larger sword/quiver/bag/wallet upgrades and Double Defense. Concrete upgrades remain available when their progressive family is in the configured pool. Fractional magic is offered in combined mode. Existing user priority lists and their order are preserved.

The caller compares both the placed progressive family and the obtainable converted tier. Converted junk from a maxed chain is rejected before priority matching. Desired Items can resolve a concrete tier through the placed progressive chain; it does not call unrelated converters. Saria still checks reachability, shuffled status and collection status. The Sensor still refuses to charge when its outstanding-check search finds no answer.

OoT's Desired Items already enumerates all named items, including Magic Stat Upgrade, and its separate Saria magic hint already supports the fractional upgrade. Those routes are retained. This change does not create a new cross-world search: MM's configurable Saria priority and Sensor use their existing local MM check scans, including upgrades belonging to OoT placed at MM checks. An upgrade physically located at an OoT check is not a new MM Sensor target supplied by this change. In-game inspection of existing seeds remains necessary.

Validation: `python3 -B tests/magic_hints/run_tests.py` compiles the actual policy with native MM types in original and Combo configurations under ASan/UBSan. It also executes the production candidate-builder, placement-search function and Saria matching/eligibility block against fixture engine boundaries. Cases include normal and fractional identities, concrete meter tiers, larger upgrades, full chains, foreign trap exclusion, and mode availability. The real nlohmann JSON dependency is required. Independent source review found no remaining blockers after correcting saturated-chain and trap eligibility. Full GUI build and in-game verification remain pending.

All POC3a UI, shovel, winter, Lost Woods ritual, mask visibility/accent and Couple's Mask recovery changes remain included.
