# Original Din's Fire audio candidate

These are original procedural spell cues, authored for the enabled native Din's
Fire remake. No vanilla game audio, reference-clip soundtrack, third-party
recording, voice, or music is used as input. This is a proposed sound design for
listening; it does not claim to match a reference recording or to have been
accepted in game.

The complete source recipe is
`scripts/assets/build_dins_fire_audio.py`. The immutable runtime data is
`combo/assets/dins_fire_sfx_pcm.inc`. Both hosts consume the same mono signed
16-bit arrays at 32,000 Hz, with no runtime decoding or external sound-pack
dependency. Total decoded data is 412,800 bytes per host, below the 512 KiB
budget. The `.inc` is self-contained C/C++ and defines
`CW_DINS_SFX_SAMPLE_RATE` plus the five `static const int16_t` arrays.

| Cue / array | Duration | Design intent |
|---|---:|---|
| charge / `kCwDinsChargePcm` | 1.00 s | Soft gathering air with stationary spectral bands and a smooth swell |
| contact / `kCwDinsContactPcm` | 0.35 s | Quiet filtered flame catch with a rounded onset |
| release / `kCwDinsReleasePcm` | 1.30 s | Flame blooming over roughly a quarter-second, with a softer receding tail |
| loop / `kCwDinsLoopPcm` | 3.20 s | Quieter warm flame and sparse softened crackles for the sustained field |
| burnout / `kCwDinsBurnoutPcm` | 0.60 s | Soft breath of embers settling away |

Recipe version 2 responds to cor's feedback that the first buildup sounded like
a racecar and the ignition was too explosive. It removes the charge's low rising
oscillator and accelerating amplitude modulation, replaces the bass contact
thud with a quiet noise-based flame catch, and removes the release's sub-bass
layer and sharp onset. Charge/contact/release peaks are reduced to 0.22, 0.14,
and 0.30 of signed-16 full scale, respectively. The new contact is subordinate
to the release, replacing version 1's intentional impact-first balance. These
are tuning decisions for another listening candidate, not user acceptance.

Loop and burnout PCM are held byte-for-byte unchanged from version 1. The
revised cues retain exactly the original random-call sizes/counts so subsequent
PRNG state is unchanged; explicit baseline hashes in the recipe and manifest
guard both preserved clips. All five durations and the 32 kHz format are
unchanged. No gameplay, engine, cue timing, or visual changes are part of this
revision.

The full loop array is the repeating region. FFT noise is periodic, modulation
uses whole cycles, and crackle envelopes wrap around the period. A final circular
rotation chooses a quiet, low-slope boundary. No attack or burnout is embedded
in the loop. This preserves the natural texture across repetitions without a
hard splice; the engine handles starting/stopping fades. Other clips have zero
samples at both endpoints.

## Reproduction and checks

Run from the repository root:

```sh
python3 scripts/assets/build_dins_fire_audio.py
python3 scripts/assets/build_dins_fire_audio.py --check
```

Python 3 and NumPy are offline authoring tools only. The authoring environment
used NumPy 2.3.5 with explicit PCG64 seed `0xD175F1AE`; no packages or recordings
are downloaded. The generated include and manifest are checked in, so a native
build does not invoke this script. The recipe uses floating-point FFTs; a future
NumPy/platform change could affect a sample near a quantization boundary.
`--check` compares exact generated bytes to detect such drift rather than
silently accepting it.

The generator checks expected lengths, finite synthesis, signed-16 bounds,
headroom, small DC, zero one-shot endpoints, loop-edge continuity compared with
ordinary adjacent samples, relative cue dynamics, and the decoded memory budget.
The manifest records exact little-endian PCM hashes, include hash, peak/RMS
levels, DC, endpoint values, and loop-boundary metrics. No time-dependent data is
written, and `--check` never changes checked-in files.

Optional source-clip WAVs and an offline recipe mix can be written outside the
repository:

```sh
python3 scripts/assets/build_dins_fire_audio.py --check \
  --audition-dir /path/to/scratch/dins-audio
```

`dins_fire_offline_recipe_audition.wav` places charge at 0.00 s, contact at
1.00 s, release and loop at 1.05 s, then fades the loop and starts burnout at
7.35 s, ending at 7.95 s. It sums the exact PCM clips without normalization and
checks the resulting stack for clipping. This optional file is a **recipe
audition**, separate from a production mixer audition: it does not model host
gain smoothing, attenuation, pan, pause, cancellation, or audio-buffer timing.

## Preservation and evidence limits

This asset change owns no gameplay timings or global vanilla sound IDs.
Integration scopes these arrays to the latched remake and separately preserves
voice/floor feedback, stock casts, other spells, visuals, damage, interaction,
and actor lifetime. Mixer gain and cue ownership live in the native audio code.

Numerical checks demonstrate signal bounds and repeatability; they do not prove
that the proposed design sounds good, that the runtime mix is balanced against
music/voice, or that the effect has been heard in a linked game. Listening to the
production mixer audition and then the configured game is still necessary.
The sacred baseline is unchanged and this candidate is not promoted by the
presence of generated assets or passing numerical checks.
